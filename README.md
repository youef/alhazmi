# ديوان الحازمي | Alhazmi Tribal Registry

منصة أهلية **قيد التطوير** لإدارة شجرة الأنساب والسجلات العائلية والخدمات الاجتماعية، وليست جهة حكومية أو بديلًا عن الأحوال المدنية.

> **حالة المشروع:** مستودع تأسيسي: مخطط قاعدة بيانات وخطة تنفيذ ومواصفات ومعايير أمان. لا توجد بيانات أفراد حقيقية ولا نظام إنتاج منشور.

## النطاق
- شجرة نسب متعددة الاتجاهات، وحاسبة صلة القرابة ومسارها؛ روابط لكل الأب والأم والأجداد والأبناء والأعمام والأخوال والأزواج.
- بحث بالاسم والنسب وتاريخ العائلة مع فصل الأسماء المتشابهة.
- التوثيق والمراجع والشهادات وسجل تدقيق لا يقبل التعديل من المستخدمين.
- المواليد والوفيات والزواج والطلاق وطلبات تصحيح النسب.
- أرشيف المخطوطات والصور، الشخصيات البارزة، صندوق التكافل، الإحصائيات.
- صلاحيات مدير النظام، مشرف الفخذ، مشرف العائلة، النسابة، المسؤول المفوض، وعضو القبيلة.

## الملفات
- `supabase/migrations/20261115000000_initial_schema.sql`: قاعدة البيانات الأساسية.
- `supabase/migrations/20261115001000_security_policies.sql`: عزل الجداول والصلاحيات الأولية RLS.
- `docs/PROJECT_PLAN.md`: الخطة التفصيلية ومراحل التنفيذ ومعايير القبول.
- `docs/DATA_MODEL.md`: العلاقات والحقول وقواعد صحة النسب.
- `docs/SECURITY.md`: تصنيف البيانات والخصوصية وحوكمة الوصول.
- `docs/ARCHITECTURE.md`: التقنيات والتخطيط للواجهات والمهارات المطلوبة.

## أول تشغيل
1. أنشئ مشروع Supabase **خاصًا** للتطوير وأبقِ مفاتيح الخدمة في بيئة الخادم فقط.
2. راجع ملفات SQL، ثم طبقها بالترتيب في بيئة **اختبار** مستقلة أولًا.
3. لا تضع هويات أو عناوين أو وثائق أشخاص حقيقيين في GitHub أو بيانات تجريبية عامة.
4. أنشئ عمليات اعتماد الطلبات ومنح الأدوار كواجهات خادم محمية مع اختبارات صلاحيات قبل ربط واجهة عامة.
5. لا تفتح أي جدول للقراءة العامة تلقائيًا. السياسات التأسيسية مقفلة (deny-by-default).

## قواعد مهمة
علاقة الأبوة والأمومة لا تستنتج من الزواج وحده، والزوج السابق أو زوج الأم ليس أبًا بيولوجيًا تلقائيًا. كل تعديل بالنسب يمر بطلب وتوثيق واعتماد مع الاحتفاظ بسجل تاريخي. صلاحية إدارة الفخذ لا تمنح آليًا الاطلاع على الهوية والعنوان الوطني.
