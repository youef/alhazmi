# التوسعة V2 — تفاصيل الأسماء والبيانات
هذه التوسعة تضيف 27 جدولًا بسجلات مفصلة للأنساب والهوية والزواج والرعاية والتعليم والوظائف والسكن والهجرات والتفويضات والنسابة والإشعارات والإحصائيات والتدقيق والتعارضات.

## مثال تقسيم الاسم
الاسم الذي قدمه صاحب المشروع في المحادثة **مثال لهيكلة البيانات وليس بيانات مدخلة في قاعدة المشروع**:

| الترتيب | الجزء | التصنيف المقترح |
|---|---|---|
| 1 | يوسف | الاسم |
| 2 | ثنيان | الأب (بعد التحقق من النسب) |
| 3 | رطيان | الجد (بعد التحقق) |
| 4 | مطر | اسم سلف |
| 5 | غنايم | اسم سلف |
| 6 | الشجراوي | عائلة/فرع *بحاجة توثيق* |
| 7 | الدرويشي | فخذ *بحاجة توثيق* |
| 8 | الحازمي | القبيلة حسب وصف المستخدم |

**لا تُستنتج العائلة والفخذ تلقائيًا من موضع الكلمة فقط.** `person_names` يسجل النسخ التاريخية والألقاب والكنى، و`person_name_parts` يحفظ كل مقطع وترتيبه ويربطه اختياريًا بشخص سلف أو بوحدة نسب.

## رقم الهوية المكرر
`person_identifiers` يخزن بصمة HMAC-SHA256 سرية للمعرف بعد توحيد صياغته مع نوعه وبلده وجهة الإصدار. فهرس فريد يمنع تكرار نفس الهوية النشطة. لا تحفظ رقم الهوية الصريح، ولا تجعله ظاهرًا في الشجرة أو البحث. خزّن قيمة مشفرة فقط عند الضرورة القانونية والتشغيلية. المفاتيح في KMS خارج قاعدة البيانات؛ المفتاح غير موجود في GitHub. استعلام التحقق يجب ألا يكشف هوية صاحب الرقم الآخر.

تنبيه هندسي: عند تدوير مفاتيح HMAC، يجب تطبيق آلية انتقال تتحقق من جميع نسخ المفاتيح، وإلا قد يدخل نفس الرقم مرتين بإصدارات مفاتيح مختلفة.

## الروابط
- `ancestral_roots`: أجداد مؤسسون مع مصادر.
- `person_birth_records`: مولد وجنسية ومكان وتوثيق.
- `marriage_history`: أحداث زواج/طلاق/ترمل مرتبطة بزواج رئيسي.
- `child_care_records`: حضانة ووصاية وكفالة؛ منفصلة تمامًا عن النسب البيولوجي.
- `person_education`, `person_employment`: تعليم ومهن مع تواريخ.
- `places`, `place_aliases`, `person_residences`, `historical_settlements`, `family_migrations`: سكن وانتقال ومواقع.
- `family_delegations`, `guardian_permissions`: تفويض محدود ومؤرخ، لا يجعل بيانات الطفل عامة.
- `genealogists`, `verification_tasks`, `expert_opinions`: التحقق من النسب.
- `notifications`, `notification_preferences`: الإشعارات.
- `family_statistics`, `statistics_snapshots`: أرقام مجمعة مع حجب المجموعات الصغيرة.
- `record_revisions`, `audit_events`: التاريخ والتدقيق.
- `data_conflicts`, `conflict_resolutions`: تعارضات المعلومات.

## حالة التنفيذ
تم رفع مخطط الجداول فقط. لم يتم ربط Supabase وتشغيل SQL أو اختبار RLS بعد. الوصول للبيانات مقفل افتراضيًا. يلزم تنفيذ صلاحيات خادم محددة لكل عائلة وفخذ، التشفير التطبيقي، وإجراءات اعتماد وتدقيق قبل إدخال بيانات أشخاص حقيقية. تحتاج أيضًا قواعد تحقق الاتساق بين القبائل ومنع دورات الفروع والأماكن.
