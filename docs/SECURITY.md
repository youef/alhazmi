# الخصوصية والأمان — قبل استخدام بيانات فعلية

**هذا المستودع عام؛ لا ترفع أي هويات أو وثائق أو أرقام جوال أو عناوين حقيقية إليه.**

## المبادئ
- إغلاق جميع الجداول بـ RLS + REVOKE افتراضيًا؛ عدم فتح SELECT شامل لمجرد تسجيل الدخول.
- تفويض مركّب: دور + نطاق فخذ/عائلة + غرض الوصول + موافقة/تفويض + حالة الفرد حي/متوفى.
- مشرف الفخذ لا يقرأ `person_private` لمجرد إشرافه؛ كل حقل حساس يحتاج صلاحية منفصلة ومسار تدقيق.
- بيانات الهوية والعنوان الوطني والاتصال تُشفّر تطبيقيًا بمفاتيح KMS خارج قاعدة البيانات، ولا تُرسل إلى تحليلات أو logs.
- لا تخزّن مفاتيح service_role أو مفاتيح فك التشفير في الواجهة أو Git أو ملفات عامة.
- حفظ صور الأطفال أو بياناتهم الخاصة أو معلومات الزوج السابق مقيد بسبب مشروع ورضا/أساس قانوني مناسب.
- المحتوى العام يتطلب مراجعة، وتستطيع الأسرة طلب الإخفاء والتصحيح وفق السياسة والنظام.
- محرك البحث والشجرة وحاسبة القرابة تُطبَّق عليها نفس حدود الرؤية؛ عدم تسريب تفاصيل مخفية في النتيجة أو المسار أو الإحصائيات.
- المرفقات في buckets خاصة، مع روابط موقعة قصيرة الصلاحية وحظر مشاركة روابط مستقرة للوثائق.

## متطلبات قبل الإنتاج
1. تعريف جهة التحكم في البيانات والسياسات والاحتفاظ والإتلاف والتظلمات بما يلائم نظام حماية البيانات الشخصية السعودي.
2. وظائف backend لإسناد الأدوار ومراجعة الطلبات وتطبيق التغييرات داخل معاملات محمية ومُدققة.
3. سياسات RLS مخصصة ومختبرة لكل جدول وعمليات SELECT/INSERT/UPDATE/DELETE، واختبار IDOR والوصول بين الأفخاذ.
4. تأكيد النزاهة وقابلية اكتشاف التلاعب لسجل التدقيق عبر append-only وحساب hash/أرشفة خارجية.
5. تشفير خارجي وإدارة تدوير المفاتيح، نسخ احتياطية واختبار استعادة، مراقبة، تحديد معدل الطلبات، MFA للمسؤولين.
6. صندوق التكافل: مراجعة المتطلبات النظامية لجمع التبرعات والتعامل مع الأموال قبل تفعيل التحصيل.
7. لا توثيق حكومي أو ادعاء ارتباط بالأحوال المدنية أو نفاذ دون الاعتماد الرسمي المطلوب.

## حدود التأسيس
المهاجرات الحالية **ليست بحد ذاتها ترخيصًا للإطلاق**: لا توجد سياسات وصول تفصيلية بعد، ولا تنفيذ مكتمل لمسارات مراجعة البيانات أو سجل تدقيق مقاوم للعبث. استخدم بيانات تجريبية فقط.
