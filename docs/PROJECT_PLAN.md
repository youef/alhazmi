# الخطة التنفيذية — ديوان الحازمي

## رؤية المشروع
منصة أهلية غير حكومية لإدارة أنساب القبيلة وسجلات الأسر والتكافل والأرشيف، ذات واجهة RTL متجاوبة (ويب ثم PWA)، وتتدرج من بيانات تجريبية إلى سجلات موثقة بموافقات وضوابط خصوصية.

## حدود الإصدار التأسيسي (الموجود في المستودع)
- مخطط PostgreSQL للفروع والأفراد والأبوين والزيجات والمصادر والتغييرات والمناسبات والأرشيف والتكافل.
- فصل البيانات الخاصة عن شجرة النسب العامة، وقفْل الوصول الافتراضي.
- خطة معمارية وصلاحيات واختبارات مطلوبة.
**غير منفذ بعد:** واجهة الإنتاج، حاسبة القرابة التشغيلية، محرك البحث، المصادقة والنشر، اعتماد الطلبات، تطبيق RLS التفصيلي، تخزين الوثائق والمدفوعات.

## المراحل

### المرحلة 0 — الأساس والأمان
- تحديد ميثاق البيانات، الأغراض والأساس النظامي للمعلومات والموافقات والاحتفاظ والحذف.
- بيئة تطوير/اختبار منفصلة؛ أسرار في Secret Manager؛ سجلات تدقيق ونسخ احتياطي.
- مراجعة المخطط، قيود تناسق القبيلة بين الأشخاص والفروع، واختبارات SQL.
**معيار القبول:** لا يستطيع المستخدم غير المصرح رؤية أي صف، ولا توجد بيانات حقيقية داخل Git.

### المرحلة 1 — التسجيل والشجرة
- تسجيل Supabase Auth، ربط حساب مع سجل الشخص بعد إثبات ملائم.
- CRUD محمي للفروع والعائلات والأشخاص والزيجات والحالات مع طلبات اعتماد.
- رسم شجرة ثلاثية الاتجاهات قابلة للتوسيع وطي الفروع والبحث على الشخص.
- كل بطاقة قابلة للفتح، وتسلسل الأجداد/الذرية من جانبي الأب والأم.
**معيار القبول:** حالات متعدد الزوجات والزواج السابق والإخوة من الأب والأم والأعمام والأخوال لا تُخلط.

### المرحلة 2 — البحث وحاسبة القرابة
- تطبيع العربية (أ/إ/آ، التشكيل، المسافات) مع البحث النصي والفهرسة.
- حاسبة مسار القرابة عبر BFS على رسم بياني للوالدين فقط، ثم توليد وصف عربي دقيق للمسارات المعروفة؛ صلة المصاهرة مميزة ولا تعامل نسبًا.
- إظهار مسار النسب ومراجع كل رابط، والتحذير من الروابط المتنازع عليها.
**معيار القبول:** الاختبارات الذهبية تغطي جد مشترك، خال، عم، ابن عمة، أخ غير شقيق، زوج سابق؛ ولا تعلن نتائج غير مؤكدة.

### المرحلة 3 — التوثيق والأحداث والأرشيف
- سير مراجعات مع فصل مقدم الطلب والمراجع وتوثيق المصادر، وطلبات إضافة/تصحيح/ميلاد/وفاة/زواج/طلاق.
- سجل تغييرات append-only مدعوم بتدقيق على مستوى قاعدة البيانات؛ منع حذف الوثائق دون تاريخ.
- تخزين خاص بوصول مؤقت ومراجعة المحتوى قبل نشر سيرة/صورة.
**معيار القبول:** اعتماد طلب يُحدّث سجل الأنساب مرة واحدة فقط في معاملة موثقة، مع سجل قبل/بعد.

### المرحلة 4 — التكافل والتقارير
- محفظة/صندوق محاسبي إداري، تبرعات ومساعدات وموافقات مزدوجة، إيصالات بدون تخزين بيانات البطاقات.
- إحصائيات مجمعة بتصاريح وحجب فئات صغيرة تكشف الأفراد، وتصدير CSV/PDF.
**معيار القبول:** تسوية مجموع الأرصدة وإلغاء العمليات بعملية عكسية، لا بحذف التاريخ.

### المرحلة 5 — الاستقرار والإطلاق
- اختبارات أمنية RLS، اختبارات ضغط ~100,000 سجل وهمي، وصولية WCAG، نسخ احتياطي واستعادة، مراقبة، سياسة حوادث، ونشر مرحلي.

P0: أمان/توثيق/سجل أفراد وشجرة وطلبات. P1: حاسبة القرابة وبحث عربي والأرشيف. P2: التكافل والتقارير والتوسع.

## إدارة العمل
- Feature branches + PRs + مراجعة إلزامية للمهاجرات وRLS.
- Test data اصطناعية فقط، وبيئات staging وproduction منفصلة.
- كل ميزة: مخطط + سياسات + واجهة + اختبارات سلبية للصلاحيات + توثيق.
