# قاعدة البيانات: فحص ما قبل الإصلاح

الترتيب المعتمد:
1. أخذ نسخة احتياطية من قاعدة التطوير/الاختبار.
2. تطبيق V1–V4 إن كانت بيئة جديدة.
3. تشغيل `tests/preflight_data_integrity.sql` في بيئة staging، ومراجعة كل نتيجة غير فارغة. المخرجات قد تحتوي معرّفات سجلات؛ لا ترفعها إلى مستودع عام.
4. التعامل مع البيانات المخالفة بقرارات موثقة؛ لا تمسح بيانات النسب تلقائيًا.
5. تطبيق `20261115005000_integrity_hardening.sql` بعد حل التعارضات.
6. تشغيل `tests/schema_integrity_checks.sql` ثم اختبارات معاملات CRUD والصلاحيات تحت مستخدمين مختلفين.
7. تحقق من أداء البحث وحاسبة القرابة عند مئات آلاف السجلات قبل فتح النظام.

القيود الجديدة تمنع إدخال بيانات خاطئة مستقبلًا لكنها لا تنشئ واجهات مستخدم أو تُصلح أنساب أشخاص تلقائيًا. أي تعديل لحقيقة نسب يمر بطلب موثق ومراجعة مسؤولة.

**الحالة:** تم رفع سكربتات الفحص والإصلاح للمستودع. لا توجد بيئة Supabase مستقلة باسم alhazmi ضمن المشاريع المتصلة، لذلك لم يتم تشغيل الإصلاحات على قاعدة حية.
