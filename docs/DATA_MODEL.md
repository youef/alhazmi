# نموذج البيانات والعلاقات

## التسلسل القبلي
`tribes → lineage_units(parent_id,unit_type) → people(family_unit_id)`؛ أنواع الوحدات: فرع/بطن/فخذ/عائلة/بيت. بنية وحدات مرنة، ويمنع في طبقة الخدمة نقل وحدة أو فرد عبر قبيلة بدون موافقة إدارية.

## النسب والأسرة
- `people.father_id` و`people.mother_id`: روابط الوالدين المعتمدة الأساسية، لا تُشتق من حالة الزواج.
- `parentage_assertions`: ادعاءات ومراجع مستقلة (أب، أم، وصي، زوج أم/أب، كفالة) بحالات مراجعة؛ لا تحل محل الروابط المعتمدة تلقائيًا.
- `marriages`: صف لكل زواج مهما تعدد أو انتهى؛ `partner_a_id` و`partner_b_id` لا يوحيان بمن هو الوالد.
- الأعمام = إخوة الأب؛ الأخوال = إخوة الأم؛ الأحفاد = أبناء الأبناء والبنات؛ الإخوة الأشقاء يشتركون في الأب والأم؛ إخوان الأب/الأم يميزون كلٌ على حدة.
- صلة المصاهرة تُرسم بمسار متقطع مميز؛ لا تُخمن أبوة من زواج سابق.

## الحقول
`people`: اسم ومقاطع اسم وتطبيع، جنس، ولادة/وفاة مع درجة دقة التاريخ، الأسرة، مكان الميلاد، الحالة، الخصوصية والمراجعة.
`person_private`: رقم الهوية ووسائل التواصل والعنوان الوطني والوظيفة مشفرة خارج عميل الويب؛ آخر 4 أرقام للتمييز الإداري فقط.
`user_profiles`: مستخدم ↔ سجل فرد (اختياري إلى أن يتم التوثيق).
`role_grants`: أدوار بنطاق قبيلة/وحدة وتواريخ صلاحية؛ `care_delegations`: التفويض المحدد النطاق والمدة.
`change_requests`,`request_reviews`,`sources`,`evidence_links`,`audit_log`: التوثيق والتدقيق.
`person_events`: ميلاد/وفاة/زواج/طلاق وغيرها.
`archive_items`,`archive_people`,`notable_profiles`: الأرشيف والسير.
`welfare_funds`,`welfare_cases`,`welfare_transactions`: التكافل وأثره المالي.

## خوارزمية القرابة
1. جلب رسم الأبوين المعتمدين فقط داخل النطاق الذي يُسمح باستعراضه.
2. إيجاد أقصر مسار عبر BFS مع حد عمق وتحذير إن كان المسار متعددًا أو غير موثق.
3. توليد وصف صلة القرابة عبر أنماط مركبة (الأب ← أخوه = عم؛ الأم ← أختها = خالة؛ الأب ← عمه = عم الأب).
4. إظهار العقد والخطوط والجد المشترك وروابط المصادر، ولا تقطع روابط غير مؤكدة على أنها حقائق.

## جودة البيانات
- منع الدورة في روابط الأبوين والربط الذاتي.
- تحذيرات تاريخ الميلاد والوفاة وعمر الوالدين (لا رفض آلي للتواريخ التقريبية القديمة).
- فحص التكرار بالاسم والنسب والتاريخ وملف العائلة؛ الدمج بطلب اعتماد، وليس تلقائيًا.
- النسب المختلف عليه حالة مستقلة وليس حذفًا للحقيقة التاريخية.
- لا يوجد بيانات حقيقية seed في المشروع.
